## Protocol Security

VoteChain V3 implements several protocol-level hardening measures:

- **On-Chain Idempotency**: Every vote includes a `kiosk_nonce` generated by the edge device. The `VotingV2` smart contract rejects any transaction with a previously used nonce, preventing replay attacks.
- **Sequential Vote Queue**: The backend processes transactions via a sequential queue to prevent Ethereum nonce collisions and improve stability under load.
- **Fail-Safe Reconciliation**: Votes are initially persisted as `PENDING` states in the database. Successful blockchain confirmation triggers an update to the final transaction hash and a `is_confirmed` flag.
- **Session Tokens**: Voting requires a signed `session_token` obtained during biometric check-in, preventing direct API injections without hardware presence.
- **Kiosk Hardware Hardening**: Fingerprint verification is limited to **max 2 attempts** with clear audio-visual feedback to reduce frustration while preventing enumeration.
- **Service Discovery Logic**: The kiosk uses a dynamic discovery mechanism via Supabase, ensuring it can always find the moving target of a Cloudflare Tunnel backend.

## Database & RLS

- **`system_config`**: Restrict UPDATE permissions to the `service_role` to prevent unauthorized backend URL hijacking.
- **`receipts`**: Use unique indexes on `code` and `tx_hash` to maintain audit trail integrity.
- **`voters`**: Aadhaar IDs are salted and hashed (SHA-256) before storage; the primary database contains PII but the blockchain entry is anonymous.
- **`enrollment_requests`**: [PII PROTECTED] Public read access is strictly disabled. Only the backend `service_role` can access the enrollment queue.

## Incident response (brief)

- **Key Compromise**: Rotate `SERVER_PRIVATE_KEY` and `ADMIN_SECRET` immediately.
- **Blockchain Issues**: The `SimpleVoteQueue` logs persistent errors; monitor these for RPC provider failures or gas price spikes.
